# iter2: multi-camera master view, counts, classes and positions

Run everything from this folder (`cd iter2`): the default relative paths (`data/`, `results/`) assume it. Results and conclusions: `FINDINGS.md`; every number in it is compiled in `REPORT.md` (`make_report.py`).

## Setup
- Used: Python 3.14, torch 2.14 (cu130), diffusers 0.41, transformers 5.17, torchvision, opencv 5.0, scipy, pillow; one RTX 3070 laptop GPU (8 GB). Windows.
- Imports three iteration-1 modules from `../iter1`: `mmsd_sender.py`, `receiver_smoke_test.py`, `palette_test.py`.
- Models download from Hugging Face / torchvision on first use (Stable Diffusion 1.5, ControlNet canny and seg, Mask2Former, BLIP, Faster R-CNN v2). `prefetch_iter2.py` pre-downloads the IP-Adapter (and an RT-DETR checkpoint that was fetched but is not used).
- Dataset locations are in `paths.py`; override with `CSCI408_CARLA_KIT`, `CSCI408_CARLA_V2`, `CSCI408_CARLA_V3`, `CSCI408_REAL_WORLD`. The CARLA datasets are generated by `../carla` (see its README); they are not in git.

## Pipeline (order of use)
```
python payloads.py     --dataset DIR --out data/NAME [--cases 1-20]
python coordinator.py  --payloads data/NAME --out results/NAME --variants k1,prompt_only [--cases 1-112] [--size 1280x704] [--cn-scales 1.0,1.0]
python analysis.py     --out results/NAME --dataset DIR --payloads data/NAME --variants k1,prompt_only
python geofuse.py      --out results/NAME_geofuse --manifest DIR/manifest.json --payloads data/NAME --min-area 10 --gate 2.5
python eval_union.py   --manifest DIR/manifest.json --geofuse results/NAME_geofuse --analysis results/NAME/analysis --variants oracle_gen,k1,prompt_only --out results/NAME_eval_union.json
python make_report.py
```
Variants: `k1` (Rec1 only), `prompt_only`, `prompt_shuffled` (control), `ipa_seg[@scale]`, `ipa_recon[@scale]` (needs `--k1-cams all` first). Each stage is resumable (finished outputs are skipped). `eval_union.py` needs a v3-style manifest (instance ids and world positions); `analysis.py` and `geofuse.py` work with v2 as well.

Output per case (`results/NAME/analysis/<variant>/caseK.json`): counts per class and every detection with class, score, and pixel position in the master view and in the camera's 1920x1080 frame. `analysis/counts.csv` and `analysis/detections.csv` hold the same in tables; `analysis/summary.json` the aggregates.

## Other files
- Analysis helpers behind figures in `FINDINGS.md`: `blob_count.py` (blob counting on the received segmentation maps), `payload_recall.py` (which vehicles are present in the payload), `sizebins.py` (recall by box size), `geom_check.py` (pose-convention check), `sweep_gf.py` (fusion settings sweep), `compare_tune.py`, `compare_hr.py`.
- `ops/`: PowerShell used to run long jobs as Windows scheduled tasks on one machine. They contain absolute paths and are a record, not portable tools.
- `_scratch/` (ignored): one-off patch and inspection scripts.

## What is committed
Code, `FINDINGS.md`, `REPORT.md`, and the small result files (`summary.json`, `counts.csv`, plus `detections.csv` for the three main runs, `v3_eval_union.json`). `data/` (payloads), `results/` (images, per-case JSON), `jobs/` and logs are generated and ignored; the committed summaries were added with `git add -f`.
